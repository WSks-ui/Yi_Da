# 数据持久化与文件

> 导航入口：[数据管理](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/data-management) · [Preferences](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-preferences) · [关系型数据库](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-relational-store) · [文件管理](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-file-management)

先按数据语义选择存储，再核对当前 SDK 的 API 签名、错误码、安全级别和生命周期要求。

## 选择存储

- Preferences：少量配置和简单键值，不承担复杂查询或大对象存储。
- RDB：结构化数据、查询、索引、事务和版本迁移。
- 文件：文档、媒体、流式或大块数据；需要明确路径、URI、所有权和原子性。
- 分布式数据：只有明确跨设备一致性、会话和冲突语义时使用。

不要因为 API 可用就默认它满足敏感数据、备份、同步或删除需求。

## Preferences

- 定义 key、类型、默认值、缺失值和旧版本值的迁移语义。
- 写入完成与持久化完成可能是不同边界；根据业务耐久性要求核对官方契约。
- 监听器需要稳定回调身份和解绑路径。
- 不存放不适合明文键值存储的凭证或敏感材料。

## RDB

- `StoreConfig` 的安全级别、加密和位置由数据敏感性与项目兼容要求决定。
- 建表与升级脚本必须覆盖已有安装，而不仅是新安装。
- 多步修改需要定义事务边界、失败传播、提交和回滚。
- 每个 `ResultSet` 都要在成功、异常、取消和提前返回路径关闭；优先使用清晰的 `try/finally` 所有权。
- 查询条件、排序、分页、唯一性和并发写入要符合业务不变量。
- 不拼接不可信 SQL 输入；使用 API 支持的参数化方式。

## 文件与 URI

- 区分沙箱路径、用户选择 URI、媒体 URI、临时文件和外部来源。
- 验证输入路径或 URI，避免目录穿越、错误覆盖和跨边界访问。
- 写入重要文件时设计临时写入、同步、原子替换和失败恢复。
- 文件句柄在所有路径关闭；大文件使用适合的流式或异步方式。
- 删除前固定精确边界，处理文件不存在、占用、权限失败和部分成功。
- 读取时处理短读、编码、超大输入、格式损坏和版本不兼容。

## 数据生命周期

- 明确创建、读取、更新、删除、退出登录、卸载/备份和隐私删除语义。
- 敏感数据不写入日志；密钥由合适的安全能力管理。
- 缓存和源数据分开，避免把可重建缓存当作唯一真相。
- 异步保存与页面退出、进程终止、重复保存之间需要明确契约。

## 验证

- 新安装、从旧 schema 升级、降级边界（若支持）。
- 空数据、损坏数据、磁盘满、权限失败、并发写入和中途取消。
- `ResultSet`/文件句柄清理和事务回滚。
- 真机数据目录、URI 授权和系统选择器行为；未运行时明确说明。
