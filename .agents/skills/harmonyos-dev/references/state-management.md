# 状态管理与响应性

> 导航入口：[状态管理概述](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-state-management-overview) · [状态管理 V1/V2 迁移](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-v1-v2-migration)

装饰器和混用规则会随 SDK 演进。先识别项目与组件使用的状态管理版本，再打开当前官方文档核对具体约束。

## 选择与一致性

- 现有组件：沿用其 V1 或 V2 模型，除非任务明确要求迁移。
- 新组件：结合项目基线、兼容 API 和相邻代码选择，不把 V2 自动等同于无条件可用。
- 迁移：单独列出装饰器映射、父子同步语义、持久化桥接和兼容 API；不要只做名称替换。
- 组件输入、组件本地状态、跨层共享状态和持久化状态应有明确所有者。

## 实现检查

- 状态字段必须覆盖 UI 实际依赖的变更粒度。
- 父到子输入与子到父事件保持单向数据流；需要双向同步时明确更新契约。
- 对象或数组发生深层变更时，核对当前装饰器能否观察到该层级。
- 异步加载结果写回前，确认组件仍存活且结果没有被更新请求淘汰。
- `@Provider`/`@Consumer` 或全局存储的作用域不能跨越预期生命周期。
- 事件总线不是默认状态容器；需要订阅时记录回调身份并对称解绑。
- 持久化与响应式状态分层：持久化恢复失败、旧版本数据和默认值都要有明确行为。

## “数据变了但 UI 没变”诊断顺序

1. 找到 UI 读取的具体字段和表达式。
2. 找到运行时实际修改的对象、字段和引用。
3. 确认该字段受当前组件模型支持的状态装饰器观察。
4. 确认修改发生在正确实例上，而非副本、旧实例或已销毁组件。
5. 检查父子同步方向、回调是否执行、异步结果是否过期。
6. 用最小日志或测试证明“写入发生”和“渲染依赖被通知”两个节点。

不要把“getter 一定不响应”或“某两个装饰器永远不能共存”写成跨版本规则。应针对项目 SDK 和具体数据依赖验证。

## 生命周期与并发

- 注册监听的所有路径都应有对称注销路径。
- 避免旧请求覆盖新请求，可使用请求序号、取消能力或单一任务所有权。
- 保存操作需要定义重复点击、并发调用、失败重试和退出页面时的语义。
- 全局单例和应用存储需要定义初始化完成前的读取行为。

## 交付验证

- 构建受影响模块，检查 ArkTS 装饰器和类型诊断。
- 测试初始值、父组件更新、子组件事件、深层对象更新、页面重建和异步乱序。
- 若涉及 V1/V2 迁移，逐页验证 UI 刷新行为，而不是仅以编译通过为准。
