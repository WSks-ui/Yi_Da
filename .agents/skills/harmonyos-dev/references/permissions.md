# 权限与系统能力

> 导航入口：[权限管理](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/permissions) · [申请权限](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-acquire-permissions) · [权限列表](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/permissions)

权限名称、授权类型、受限策略和请求行为会变化。不要维护静态“常用权限表”；按项目 API 范围打开当前权限参考逐项核对。

## 决策顺序

1. 确认功能是否真的需要受保护能力，能否用系统选择器或更小权限替代。
2. 在 `module.json5` 中声明精确权限，并按当前文档填写 `reason`、`usedScene` 等必要字段。
3. 区分系统授权与用户授权。只有官方文档允许运行时申请的权限才调用授权 API。
4. 在用户触发相关功能时检查状态并请求，而不是无上下文地启动即请求。
5. 处理拒绝、取消、仅本次授权、设置中撤销、策略限制和永久不可申请状态。
6. 功能结束后不要继续访问无关数据；敏感数据的保存与删除另行设计。

## 实现检查

- 使用项目实际的 `Context` 和访问令牌来源，核对当前 API 的参数要求。
- 检查批量授权结果与请求权限的索引、数量和错误状态一致。
- 用户拒绝后提供可理解的降级，不循环弹窗或把拒绝当作系统错误。
- 权限授予后仍处理能力不可用、设备不支持和底层调用失败。
- 权限说明与实际用途一致，不夸大或隐藏数据使用。
- 网络、文件选择器、媒体库等能力可能有不同授权模型，不以传统“存储权限”类推。

## SysCap 与设备能力

- 权限解决“是否允许”，SysCap/API/设备约束解决“是否支持”；两者分别验证。
- 对可选能力使用官方支持的能力检查或项目兼容分支。
- 降级行为应在 UI 和业务层一致，避免入口可见但调用必然失败。

## 安全与隐私

- 只申请完成当前功能所需的最小权限集合。
- 不在日志中记录授权令牌、敏感数据或完整用户输入。
- 敏感数据的收集、存储、共享、撤回和删除行为应与产品声明一致。
- 权限已授予不代表可以无限期、无场景地使用相关数据。

## 验证

- 首次授权、拒绝、取消、仅本次授权、设置中撤销后再次进入。
- 目标设备不支持该能力或 SysCap 缺失。
- 多权限部分授予、授权 API 抛错、页面退出时授权结果返回。
- 应用升级后权限变化；真实设备/账号策略无法验证时明确记录。
