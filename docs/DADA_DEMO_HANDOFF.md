## 镜头一：顶栏搭搭 → 聊天候选 → 确认采用

1. 首页顶栏点击“光团＋搭搭”，镜头先展示同一入口与欢迎语。
2. 点击“正式一点”，或输入“上课，24度”后发送。展示回复、衣物缩略图、场合和温度。
3. 如需多轮镜头，可以点击“换一件上装”或“再来一套”；这一步只更新本轮候选，不改变当前搭配。
4. 向上滑动面板，让候选卡和“采用后更新为…”完整入镜，点击“采用这套”。
5. 面板在保存成功后关闭；进入“搭配”核对新的场合、温度和衣物。失败时保留候选，可再次点击采用或用顶部保存提示重试。

默认衣橱在课程展示场合只有一件可用上装，因此“正式一点”后再换上装可能没有替代品。拍摄替换时使用“上课，24度”，或事先录入另一件符合条件的上装；不要把无替代品提示剪成换装成功。

## 实现和验证边界

- `DadaContext.ets` 提供上下文、明确操作、候选提案和按最新衣物状态重新校验的契约；组件只发回调，`Index` 继续持有业务状态。
- `Index.submitAssistant` 只更新聊天与候选；`applyAgentOutfit` 构造候选快照，沿用 `SnapshotCommit` 先落盘再发布和刷新卡片。合法的多轮组合即使不在推荐前三名中，采用与重启后也保持一致；天气城市和来源不由助手改写。
- `GarmentRecognitionImage.ets` 显式导入 SDK 文件和图像 API，解码小尺寸 RGBA 后调用原主色算法。修复原动态 Kit 解析在模拟器上静默无主色建议的问题，失败明确降级，创建的文件、ImageSource 与 PixelMap 逐个释放。
- `TryOnPresentationController` 只持有演示状态和一个计时器，阶段、sceneId、runId 同步发布。页面挂载和 Watch 共同消费唯一请求 ID，旧运行回调无法展示结果。
- 模拟器收尾发现导出按钮曾把初始生成状态作为 Builder 参数保存，导致演示完成仍禁用。改为在 Builder 内直接读取页面状态，补全正常态透明度；过程完成后相册和分享按钮已实际恢复可点，相册保存及系统分享面板已核验。
