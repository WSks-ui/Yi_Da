# 艺搭：鸿蒙高校创新赛十天开发安排

编制日期：2026-09-13。依据用户提供的《艺搭产品设计文稿》，并按“只有鸿蒙 7 手机、有服务器但初期不接后端、没有 AI 试穿服务、先用内置数据演示”的已确认条件实施。文稿中的设计构想不等于当前已实现功能。

## 参赛定位

核心叙事：围绕学生自己的衣物，为上课、课程展示、社团和约会提供有依据、可替换的每日穿搭。演示重点是完整操作流程，以及原生系统入口带来的实际便利。

官方赛事页面评审表显示：创新性 50 分、完成度 20 分、前景评估 20 分、规范性 10 分，另有实际应用价值附加评分。这里据此安排优先级，不把接入 Kit 的数量当作评分规则。

建议答辩重点：

1. 衣物状态参与推荐约束，“待洗”不会继续出现在推荐中。
2. 推荐理由同时解释天气、校园场合与可穿状态，缺少单品时说明原因。
3. 用户可以只换一件、锁定一件或排除一件，保留对结果的控制。
4. 在鸿蒙桌面查看本次搭配，通过互动卡片查看衣物组合，再直达原生页面。
5. 原生相册选择器只读取用户主动选中的照片，本地衣橱和规则推荐离线可用。

这些组合体现产品取舍；不能声称《搭搭》没有对应能力，也不能保证获奖。

## 《搭搭》参考

已定位到“小衫重叠科技（深圳）有限公司”的《搭搭 -AI智能电子衣橱》，应用商店 ID 为 `1616484963`，Android 包名 `com.xiaoshanchongdie.dada`。依据应用商店公开说明，未进行账号内产品实测。

| 公开功能 | 艺搭的取舍 |
| --- | --- |
| 拍照、相册批量上传、自动抠图及分类 | 先实现系统相册单张导入与手动确认，后续再接识别；不能将固定分类伪装为识别结果 |
| 标签、状态、多条件筛选、批量修改 | 首版做品类、状态与搜索；五种状态直接影响推荐 |
| AI 搭配、DIY 调整、搭配收藏 | 先做可解释规则、单件替换、锁定、排除和收藏 |
| 当地天气、日程规划、穿搭日记 | 用明确标识的手动天气演示决策，穿后记录实际保存 |
| 统计、闲置管理、穿衣成本 | 首版保留穿着次数和反馈；后续再做低频衣物唤醒与成本统计 |
| 多人衣橱、跨系统同步、社区、种草衣橱 | 不纳入本次十天演示主线 |

参考成熟流程和信息层级，保持艺搭自己的文案、布局与素材。用户评论可以用来提出假设，但历史评论不能证明当前版本仍存在相同问题。

## 鸿蒙能力矩阵

| 能力 | 版本界限 | 业务落点 | 当前状态与验证边界 |
| --- | --- | --- | --- |
| ArkTS + ArkUI + Stage | 鸿蒙原生基础，非 7 独有 | 四入口与原生交互 | 已实现；已编译；已在鸿蒙 7 虚拟机逐页操作确认 |
| 系统字号资源 | 既有能力 | 全部文字跟随系统「字体与显示大小」 | 已改用 `sys.float.ohos_id_text_size_*`，并在 `AppScope` 声明 `followSystem`、上限 1.75 倍；超大字号的实际排版待真机确认 |
| 栅格与自适应列 | 既有能力 | 衣物网格与页面限宽 | 用 `repeat(auto-fit, 150)` 让列数随宽度变化，页面限宽 840vp；只在手机尺寸虚拟机上确认过 |
| 语义色与深浅色 | 既有能力 | 应用外观 | 全部颜色改为应用语义色，随深浅色资源切换；深色观感待真机确认 |
| FormExtensionAbility | 既有能力，非 7 独有 | 桌面查看当前搭配、打开应用 | 已实现；虚拟机添加成功并随温度刷新；点击直达应用已确认 |
| LiveFormExtensionAbility | SDK 类型声明自 API 20 起 | 点击展开衣物组合动效 | 已实现、已编译；虚拟机返回错误码 801（设备不支持），须在手机确认 |
| 场景互动卡片摇一摇 | 官方指南明确 HarmonyOS 7 及以上触发 | 摇动手机展开今日搭配 | 已配置 triggerTypes: shake 并实现更新回调；虚拟机无传感器，待真机确认 |
| PhotoViewPicker | 既有原生能力，非 7 独有 | 只读取主动选择的衣物图片 | 已接入；虚拟机完成选图、复制沙箱、重启恢复 |
| Share Kit 系统分享 | 既有能力，非 7 独有 | 分享本次搭配文字清单 | 已接入；虚拟机打开原生分享面板并显示清单 |
| 碰一碰精准分享 | API 26 新增轻碰坐标，接收侧为 PC/2in1 或 Tablet | 在大屏指定位置接收搭配或单品 | 只有一台手机，暂缓，不声称已实现 |
| 端侧 3DGS 重建 | 官方 7 发布公告列出的能力 | 可探索衣物展示，但不等于虚拟试穿 | 不纳入十天主线，不能替代真实尺码或合身判断 |
| Live View Kit（实况窗） | 已核实本机 SDK 提供，自 API 11 起 | 曾评估用于今日穿搭 | 该能力面向快递、出行等“进行中的实时任务”，与衣橱产品不匹配，不接入 |
| Core Vision 识别/抠图、Calendar、小艺意图 | 需逐项核实对应 API、准入与设备条件 | 录入、规划、语音入口 | 候选阶段；没有真实服务或任务时不制作虚假进度 |

互动卡片与普通卡片的数据来自同一份本地快照。普通卡片对内置衣物展示资源图片；若当前主单品为自行导入照片，普通卡片先展示名称，互动卡片读取完整本地图片。后续可用 formImages 文件描述符完成普通卡片自定义图片传输。

## 十天排期

按用户给出的剩余十天计算，具体截止时刻以已报名赛程通知为准。

| 天数 | 交付物 | 完成条件 |
| --- | --- | --- |
| D1 | 工程、示例衣橱、规则推荐和四入口 | 原生编译成功，状态和替换规则有检查；**已完成**，14 项业务检查通过 |
| D2 | 手机签名运行、界面与录入纠错 | 真实手机打通导入、修改、关闭重开；修复字体和安全区问题。**部分完成**：已改为鸿蒙 7 虚拟机联调，相册导入、重启恢复、统计刷新与短页面顶部对齐均已确认；签名与真实手机仍待办 |
| D3 | 收藏、反馈、推荐边界与状态回归 | 待洗必排除；锁定不变；缺少鞋/外套有准确原因。**虚拟机已确认**：待洗由 2 套降 1 套、季节隐藏降为 4 件可穿、5℃ 提示缺少上装、锁定后替换提示先解锁 |
| D4 | 桌面卡片与鸿蒙 7 互动 | 卡片显示当前组合；点击、摇动和直达应用录屏通过。**部分完成**：普通卡片添加与温度刷新、卡片冷热启动直达已确认；展开动效与摇一摇受虚拟机能力限制（错误码 801、无传感器），须在手机完成 |
| D5 | 素材与展示质量 | 用统一风格衣物照片替换当前示例；保留来源和演示标识 |
| D6 | 试穿展示决策 | 若准备预置三姿势结果，必须同一人物、同一衣物并标注预生成；否则保持未接入，不制作假生成 |
| D7 | 单手机高价值增强 | 按实际效果选择系统分享完善、日历规划或规则反馈优化中的一项 |
| D8 | 故障及恢复验证 | 飞行模式、取消选图、重复操作、空衣橱、归档恢复、冷启动 |
| D9 | 作品材料与三分钟演示视频 | 技术方案、功能实现表、图片来源、原创说明、演示脚本齐全 |
| D10 | 冻结演示包、签名和提交前核对 | 备用包可安装；视频与包内容一致；核对附件，按用户操作提交 |

若 D4 结束时互动卡片在具体手机上仍不稳定，现场使用普通卡片与点击入口，记录 7 专属动效的未完成状态。若 D6 没有合格的三姿势结果，不把其他人物或其他服装图作为本次试穿结果。

## 决赛后端演进

- 本地 DemoRepository 替换为服务器仓储并保留本地缓存；服装 ID、状态、温度与场合契约不变。
- 识别字段增加建议值、置信度、来源和用户确认状态。低置信度不能静默覆盖用户修改。
- 试穿任务增加 taskId、输入衣物版本、人物授权版本和服务端阶段；取消、失败和重试由真实任务状态驱动。
- 生成图保存人物、衣物、姿势与任务的关联，避免错误展示其他输入的缓存。
- 用户自主启用身体档案和照片上传；云服务的留存期限与是否用于训练以实际合同及配置为准。
- 会员体验只有在账号、额度与服务真实接入后启用；基础衣橱不随会员到期失效。
