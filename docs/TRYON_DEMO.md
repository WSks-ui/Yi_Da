# AI 试穿离线演示

当前交付的是固定配套样片的离线演示。无需 API Key，不上传人像，不运行生成模型，不扣试穿额度。
页面会等待约 0.9 秒展示模拟任务过程，完成后显示对应场景随包提供的正面结果图。等待仅用于演示交互，结果不是实时生成。

## 演示路径

首页「AI试穿」或搭配详情「试穿样片」进入试穿间；选择牛仔半裙、深蓝上衣或红色连衣裙的一组配套素材，开始模拟流程，再查看原图、固定结果或并排对比。可保存记录，重启后从快照恢复已保存场景；结果可保存相册或通过系统分享面板分享；记录支持确认删除。

这三组素材是三套不同服装与人物的独立单视角示例，不是同一套衣服的正面、侧面和背面。界面为三种姿势预留了选择槽；目前只有正面有可用图片，侧面和背面显示「待素材」并保持禁用。没有匹配素材时不复用其他场景图片。

保存结果保持 DEMO / FASHN VTON 1.5 标记。任意衣橱单品不会被映射为这三组固定结果。每组场景只有一条记录，重复保存幂等。旧版「未接入」记录保留，可删除，不补造结果。

## 代码边界

- `service/TryOnDemo.ets`：场景与记录契约、合法场景校验、去重、容量限制，以及只返回 `preset-demo` 的模拟等待方法。
- `service/TryOnDemoMedia.ets`：稳定场景 ID 与姿势 ID 到打包资源的映射、离线图片导出与资源释放；当前仅 `front` 返回资源，`side` / `back` 返回空。
- `pages/TryOnPage.ets`：场景选择、模拟状态、单视角结果、原图对比、姿势素材状态、历史查看、系统保存与分享。
- `pages/Index.ets`：继续使用统一 SnapshotCommit，候选快照落盘后才发布记录。失败不改内存；重新提交基于最新快照。
- `TryOnTask.demoSceneId`：可选字段，向后兼容。保存后通过场景 ID 从本地快照恢复预置结果，不持久化构建期资源数字 ID，`resultUris` 仍为空。

三姿势静态素材准备齐后，在 `TryOnDemoMedia.ets` 按同一 `sceneId` 增加 `side` / `back` 映射即可启用对应切换和对比。当前 `TryOnTask.pose` 仍由父级保存入口写入「正面站姿」；若保存多姿势记录，父级 `Index.submitTryOn` 还需接收并持久化 pose ID，并将唯一键扩展为场景加姿势。决赛真实接入时另行增加人像/衣物输入与真实任务状态；真实结果使用 `resultUris`，不改变历史 `demoSceneId` 的含义。联网、费用与用户授权只在真实生成入口处理。

## 2026-09-24 演示流程更新

- 每组素材先显示配套原图与服装参考图，点击按钮后进入约 0.9 秒的本地模拟状态，再显示同组正面固定结果。
- 已保存场景在打开页面时直接恢复固定结果；保存和删除继续走 `Index` 的统一快照提交。
- 正面、侧面、背面槽位由 `demoPoseResult(sceneId, poseId)` 查询资源。当前仅正面可用；侧面与背面明确显示素材待接入并禁用。
- 本次没有图像生成工具或获准的付费图像生成路径，因此没有创建或伪造三姿势图片；也没有运行实机或模拟器验收。
- 当前父级接线只提交 `sceneId`，所以记录的 `pose` 仍是正面站姿。接入其余姿势后，`Index.submitTryOn` 需要接收 pose ID，并以场景和姿势共同去重；不需要扩展 `TryOnTask` 模型字段，因为已有 `pose: string`。
