# 艺搭服务端接口契约 v1

日期：2026-09-05\
状态：待实现的项目协议，不是已经部署的 API\
范围：受控参赛测试的会话、素材、三姿势任务、结果和数据删除

本文是 P0 HTTP 接口的字段与行为基线。实现后应生成 OpenAPI 并进行契约测试；本文不假装已有可调用服务器。相册、衣橱、搭配、反馈首先在本地完成，不为每个本地页面创建远端接口。

## 1. 通用约定

- 基础路径 `/api/v1`，仅 HTTPS；实际域名由部署阶段配置。
- JSON 编码 UTF-8，字段使用 `camelCase`，枚举使用 `snake_case`。
- 所有时间为 RFC3339 UTC，例如 `2026-09-05T04:00:00Z`。
- ID 视为不透明字符串；客户端不可用任务 ID 推导存储目录。
- 除明确公开接口外，使用 `Authorization: Bearer <accessToken>`。
- 服务端生成并返回 `X-Request-Id`；客户端提供的追踪 ID 需长度与字符校验。
- 涉及写操作的请求均要求 `Idempotency-Key`，包括上传、会话激活/刷新、任务创建/重试/取消和删除。
- 幂等作用域为身份、HTTP 方法、资源路径与键；未激活时使用邀请的服务端 ID，不能信任客户端安装标识。
- 相同键、相同请求返回原资源；相同键、不同载荷返回 409。
- 幂等记录保留至少 48 小时；云素材过期不意味着可以复用旧键再次推理。
- 默认不接受未知 JSON 字段，避免客户端误以为某个参数已经生效。
- 对越权资源统一返回 404；对当前身份的过期资源返回 410。

响应体为直接资源对象，不另套 `data/data`。错误使用：

```json
{
  "error": {
    "code": "UNSUPPORTED_CATEGORY",
    "message": "当前配方只支持已验证的上装",
    "retryable": false,
    "details": {
      "field": "target.category",
      "supported": ["top"]
    }
  },
  "requestId": "req_example_01"
}
```

用户提示依赖稳定 `code` 映射，不直接向用户显示 Python 异常或服务端内部路径。

## 3. 会话与配额

### 3.1 POST /sessions

仅面向受控测试。邀请由后台人工签发，一次使用、短期有效，并绑定服务端配额。不能在所有安装包里写同一个永久邀请码。

```json
{
  "invitationCode": "TEST_INVITATION_PLACEHOLDER",
  "installationPublicId": "local_random_identifier",
  "clientVersion": "0.1.0"
}
```

响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 服务器签发的安装会话 ID |
| `accessToken` | string | 短效访问令牌，仅安全存储 |
| `accessTokenExpiresAt` | date-time | 默认目标 30 分钟，最终按安全策略配置 |
| `refreshToken` | string | 高熵随机凭据，服务端保存摘要 |
| `refreshTokenExpiresAt` | date-time | 受控测试初始目标 7 天 |
| `serverTime` | date-time | 用于时钟差异提示，不覆盖设备时间 |

`installationPublicId` 只用于关联调试，不是认证凭据。邀请码兑换要按邀请/IP 限流；拒绝无限自助创建会话绕过 GPU 配额。

### 3.2 POST /sessions/refresh

请求字段为 `refreshToken`，成功返回与激活相同的令牌相关字段。一次刷新原子轮换刷新凭据；同一幂等键的网络重传可返回相同新凭据，凭据重用但不同键按服务端安全策略拒绝并记录。

为支持响应丢失，短期幂等响应中的令牌需服务端加密存储并尽快清理，不能把明文 Token 放进普通日志或常规数据库导出。

### 3.3 会话撤销

`DELETE /sessions/current` 使访问与刷新凭据失效。注销前存在云删除待办时，提示先完成删除或保留删除状态查询方式；不能先抹掉唯一授权凭据再假定客户端仍可删除服务器数据。

本地功能不受云会话失败影响。卸载后云会话无法恢复是受控首版限制，必须依靠云 TTL 清理，而不是声称支持完整账号恢复。

## 4. 能力发现

### GET /capabilities

示例仅表示期望协议：

```json
{
  "apiVersion": "1",
  "ready": true,
  "recipes": [
    {
      "recipeId": "catvton-top-example-r1",
      "displayName": "上装静态试穿",
      "modelVersion": "EXPERIMENT_NOT_YET_FROZEN",
      "normalizationVersion": "person-768x1024-pad-v1",
      "supportedCategories": ["top"],
      "poseKeys": ["front", "side", "action"],
      "width": 768,
      "height": 1024
    }
  ],
  "limits": {
    "maxUploadBytes": 10485760,
    "maxDecodedPixels": 24000000,
    "maxDimension": 8192,
    "acceptedMimeTypes": ["image/jpeg", "image/png"],
    "maxActiveJobs": 1,
    "dailyJobLimit": 10,
    "inputTtlSeconds": 86400,
    "outputTtlSeconds": 86400,
    "jobDeadlineSeconds": 600
  },
  "privacyNoticeVersion": "tryon-cloud-v1",

  "serverTime": "2026-09-05T04:00:00Z"

```

正式服务不得发布 `EXPERIMENT_NOT_YET_FROZEN` 这样的占位模型。`recipeId` 对应不可变配置，包含模型/预处理 commit、权重校验值、精度、步数与所有影响输出的参数。

UI 根据能力展示支持类别，但仍需要本地产品白名单，两者取交集。服务端不支持的参数返回错误，不静默退到另一个模型。

### 4.1 指纹 v1 的精确序列化

将创建请求、服务端校验的资产内容摘要和不可变配方映射为下列固定结构，再序列化。不要直接哈希整个 HTTP 请求，因为请求带有临时 asset ID、授权时间和幂等信息。

| 层级 | 固定键顺序 | 值来源 |
| --- | --- | --- |
| 根对象 | `fingerprintVersion,space,outfitSnapshotVersion,outfitVersion,outfitItems,target,poses,recipeId,normalizationVersion,width,height` | v1、请求及配方 |
| `outfitItems[]` | `slot,garmentId,garmentVersion,contentHash` | 请求的完整方案上下文 |
| `target` | `category,contentHash` | 目标类别及服务端验证过的衣物文件摘要 |
| `poses[]` | `poseKey,contentHash,seed` | 各人物文件摘要及本次种子 |

`outfitItems` 以槽位字符串 ASCII 升序排列；`poses` 固定为 front、side、action。所有 ID 和版本标识限定 ASCII 字母、数字、下划线及连字符，哈希限定 64 位小写十六进制；不把用户衣物名称或其他自由文本放进此结构。整数不得为浮点或科学计数法，必需字段不允许 null，禁止额外字段。

使用标准 JSON 序列化器输出无缩进、无额外空格、无尾换行的 JSON，按上述显式建模的键顺序输出 UTF-8，再取 SHA-256 小写十六进制。数组不能由运行时集合的偶然遍历顺序决定。

客户端与服务端实现时必须新增共享的输入/规范字节/期望哈希黄金向量，至少覆盖槽位乱序、重新上传、种子变化、衣物版本变化和配方变化。本文冻结序列化规则，但尚未提供已经通过 ArkTS/Python 双端验证的实现。

## 5. 素材上传与下载

### 5.1 POST /assets

`multipart/form-data`，由网络库生成 boundary：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `file` | binary | 是 | 1 张 JPEG/PNG；已去除不必要 EXIF |
| `purpose` | enum | 是 | `person_input` 或 `garment_input` |
| `sha256` | string | 是 | 规范化上传文件的 64 位小写十六进制摘要 |
| `consentReceiptId` | string | 是 | 与本地本次确认相对应 |
| `privacyNoticeVersion` | string | 是 | 当前云处理文本版本 |

服务端流式限制大小，先校验魔数、字节摘要、解码像素和尺寸，再持久化。不接受远程 URL 输入，避免 SSRF；不信任文件名，不将路径拼接到公开目录。

幂等摘要由实际文件摘要及字段构成，与 multipart boundary 无关。重复上传幂等恢复不应产生第二份逻辑资产。跨用户不开放哈希查询或“文件已存在”的信息侧信道。

响应：

```json
{
  "assetId": "ast_person_front",
  "purpose": "person_input",
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "mimeType": "image/jpeg",
  "width": 768,
  "height": 1024,
  "byteSize": 245760,
  "createdAt": "2026-09-05T04:00:00Z",
  "expiresAt": "2026-09-06T04:00:00Z"
}
```

示例中的重复字符摘要不是实际样例图片的校验值。

上传允许先于任务创建，但必须先有上传授权。用户取消创建时，临时素材可以主动删掉，否则按照 TTL 清理。

### 5.2 GET /assets/{assetId}/content

返回二进制 JPEG/PNG，并带 `Content-Type`、`Content-Length`、`ETag` 或内容 SHA 校验头以及 `Cache-Control: private, no-store`。

P0 使用鉴权 API 直接下载，不引入公共桶或永久签名 URL。客户端下载到沙箱临时文件，校验后持久化；系统分享使用客户端生成的合规副本，不分享带 Token 的下载链接。

资产删除请求受理后立即停止新下载。既有传输和已经导出的副本无法通过简单撤销请求收回，不能声称即时收回所有副本。

## 6. 创建三姿势任务

### POST /tryon-jobs

```json
{
  "clientRequestId": "c4fefce1-04fb-42f8-a6a7-45020f4a3271",
  "recipeId": "catvton-top-example-r1",
  "space": "personal",
  "outfitContext": {
    "snapshotVersion": 1,
    "outfitVersion": 1,
    "items": [
      {
        "slot": "top",
        "garmentId": "local_garment_01",
        "garmentVersion": 1,
        "contentHash": "dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd"
      }
    ]
  },
  "target": {
    "garmentAssetId": "ast_garment_01",
    "category": "top"
  },
  "personPoses": [
    {
      "poseKey": "front",
      "personAssetId": "ast_person_front",
      "seed": 1001
    },
    {
      "poseKey": "side",
      "personAssetId": "ast_person_side",
      "seed": 1002
    },
    {
      "poseKey": "action",
      "personAssetId": "ast_person_action",
      "seed": 1003
    }
  ],
  "consent": {
    "receiptId": "consent_local_01",
    "privacyNoticeVersion": "tryon-cloud-v1",
    "confirmedAt": "2026-09-05T03:59:50Z",
    "samePersonConfirmed": true,
    "rightsConfirmed": true
  }
}
```

示例缩短了 `outfitContext.items`。实际发起时传入本次完整方案的槽位、衣物版本和哈希，不上传其他未用于试穿的服装照片。服务端可将这些本地衣物 ID 当审计上下文，但不能据此信任资产归属。

### 6.1 字段及业务校验

- `clientRequestId` 为客户端持久化的 UUID，与请求头幂等键关联。
- `personPoses` 必须恰好 3 项，`front/side/action` 各一次，种子为 `[0,2147483647]` 的整数。
- 不同姿势使用不同图片内容；实际姿势是否合适仍需质量检查，单靠不同哈希不能证明姿势正确。
- `recipeId`、类别、输出尺寸、规范化版本一致。
- 目标类别必须出现在方案中，目标文件的哈希必须匹配对应单品上下文。
- 全部云资产属于当前会话、用途正确、未删除且有效期覆盖任务 deadline。
- 服务端记录接收授权时间，并验证文本版本；客户端自报时间不是唯一审计依据。
- 创建时原子检查配额与活动任务限制，防止并发请求绕过限额。
- 参数不满足时返回具体错误，不偷偷裁图、换配方或扩大授权范围。

### 6.2 响应

返回 202、`Location` 指向任务查询路径，响应为第 7 节完整任务对象。初始 revision 为 1，姿势状态为 `queued`。

因网络错误不知道结果时，以同一个幂等键重发同一请求。原幂等记录仍在但内容已过期时返回 410，不重新扣额度或重新推理。超过幂等保留期后，客户端不得自动补发，需要用户明确新建。

`completedCount` 专指成功图数，不是已终结姿势数。`source` 为 `generated/reused`；历史/备用是客户端打开方式，不能改变服务端真实生成来源。

revision 在公开状态变更时单调递增。较旧响应不得覆盖本地较新状态。服务端不得将内部 GPU 百分比伪装为整个任务精确进度。

### 7.2 GET /tryon-jobs

查询参数：

| 参数 | 规则 |
| --- | --- |
| `limit` | 默认 20，最大 50 |
| `cursor` | 不透明游标；不与 offset 混用 |
| `status` | 可选，单个合法任务状态 |
| `clientRequestId` | 可选，精确恢复某次提交，仍按当前会话过滤 |

按 `createdAt, jobId` 倒序稳定分页；响应 `{ "items": [...], "nextCursor": null }`。这是服务器保留期内的云任务恢复，不承诺恢复手机上从未同步的完整衣橱。

### 7.3 过期与删除

素材过期不重写推理历史的成功状态。任务元数据可在约定时间内保留，姿势附带 `expiresAt`，内容请求返回 410。主动删除受理后任务从普通列表隐藏，查询返回 410 或最小墓碑，不回传人像关联细节。

## 8. 重试与重新生成

### POST /tryon-jobs/{jobId}/retries

仅父任务已终结时允许；请求带幂等键：

```json
{
  "expectedRevision": 7,
  "mode": "failed_only",
  "poseKeys": ["side"],
  "seedOverrides": [],
  "consentReceiptId": "consent_retry_01",
  "privacyNoticeVersion": "tryon-cloud-v1"
}
```

规则：

| 模式 | 可选姿势 | 种子 | 其他姿势 |
| --- | --- | --- | --- |
| `failed_only` | 原 `failed/cancelled` 项；未选择项须已成功 | 保留原种子，不接受覆盖 | 复用成功结果 |
| `regenerate` | 原任意姿势；未选择项须已成功 | 每个选中姿势必须提供不同的新种子 | 复用成功结果 |

`seedOverrides` 格式为 `[{ "poseKey": "front", "seed": 2001 }]`。请求不能把未成功也未重试的姿势放进新任务；否则无法形成三姿势结果。

服务器创建全新 `jobId`，返回 202；原任务及其 revision 不改写。新任务三姿势都存在，复用项状态为成功并保持 `originJobId/generatedAt/expiresAt`。

复用结果不延长 TTL。新任务的全部输入、复用结果需在新 deadline 前有效，缺少任何项返回 `INPUT_EXPIRED` 或 `RESULT_EXPIRED`，引导重新上传并完整新建。

重试也计入配置的任务配额，返回明确扣减口径。请求冲突返回 409，客户端重新查询并确认，不能无限自动重试。

## 9. 取消

### POST /tryon-jobs/{jobId}/cancel

请求：`{ "expectedRevision": 3 }`。

- 对 queued/running 的任务，事务写取消标志并返回 202 及更新后的对象。
- 对已经终结的任务，返回 200 当前对象，不把成功任务改为 cancelled。
- 非终态 revision 不一致时返回 409，前端重新查询后仍可再次请求取消。
- 取消接受后未提交的计算即使完成也不得发布结果；worker 提交检查有效租约与取消标志。
- 先于取消提交的成功图可以保留，并在 cancelled 任务中展示。
- 取消不删除素材；清理全部数据必须走删除接口。

## 10. 数据删除

### 10.1 POST /deletions

```json
{
  "scope": "job",
  "jobId": "job_01",
  "includeDerived": true
}
```

允许三种严格互斥请求：

| scope | 必填字段 | 范围 |
| --- | --- | --- |
| `job` | `jobId`, `includeDerived: true` | 本任务输入、结果、复用这些结果的派生任务关联数据 |
| `assets` | `assetIds`, `includeDerived: true` | 指定图片、mask、临时数据，以及所有引用它们的任务和输出 |
| `all_content` | 无 ID 字段 | 当前会话全部云素材和任务内容 |

首版只允许级联删除，不允许“删除原图但继续保留同一人像输出”的隐蔽不完整删除。多个任务共享输入/输出时先通过关联关系计算影响，客户端确认界面说明会删除关联试穿记录。

为了实现可预期语义，`job` 范围沿原任务、重试任务以及共享素材的引用边进行闭包清理，直到没有存活任务仍引用本次待删内容；只在当前身份内处理。不共享不同用户的可识别人像资产。

服务端原子创建删除记录、逻辑禁用全部相关下载与任务结果发布、标记取消；后台执行物理清理。删除请求不能等待 GPU 算完才撤销访问。

响应：

```json
{
  "deletionId": "del_01",
  "status": "pending",
  "acceptedAt": "2026-09-05T04:05:00Z",
  "completedAt": null
}
```

### 10.2 GET /deletions/{deletionId}

状态为 `pending/running/completed/failed`。仅在数据库、私有文件、mask、输出、临时副本、缓存均处理完成且无活动写入可重新发布时设为 completed。

响应可含 `retryable`、`lastErrorCode`，不得返回已经删除的原图信息。重复 POST 使用原幂等键恢复删除记录；失败记录可由清理 worker 内部重试，不让客户端不断创建新删除单。

客户端离线队列保留必要的服务器资源 ID 和删除请求 ID，不保留被删除图片本身。云端删除完成后可清除这些关联，只保留最小完成凭据。

## 11. 错误码

| HTTP | code | 客户端行为 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 标注字段，不自动重试 |
| 401 | `UNAUTHENTICATED` | 刷新一次；失败转云会话失效，本地功能可用 |
| 403 | `INVITATION_INVALID` | 重新配置合法测试邀请，不循环兑换 |
| 404 | `NOT_FOUND` | 资源不存在或不可访问，不泄露归属 |
| 409 | `IDEMPOTENCY_CONFLICT` | 停止，检查同键载荷不一致 |
| 409 | `REVISION_CONFLICT` | 重新查询后由用户确认动作 |
| 409 | `JOB_NOT_TERMINAL` | 先等任务终结或取消 |
| 410 | `INPUT_EXPIRED` / `RESULT_EXPIRED` | 重新上传/创建新任务，不伪用旧结果 |
| 410 | `CONTENT_DELETED` | 清理本地关联并停止恢复已删内容 |
| 413 | `ASSET_TOO_LARGE` | 本地压缩或重新选择 |
| 415 | `UNSUPPORTED_MEDIA` | 改用支持图片 |
| 422 | `HASH_MISMATCH` / `INVALID_IMAGE` | 重新校验，禁止继续创建 |
| 422 | `UNSUPPORTED_CATEGORY` / `POSE_SET_INVALID` | 返回试穿设置修正 |
| 422 | `CONSENT_REQUIRED` | 展示现行授权文本并主动确认 |
| 429 | `QUOTA_EXCEEDED` | 显示额度与恢复时间，不无限重发 |
| 503 | `MODEL_NOT_READY` | 稍后查询能力，允许本地闭环 |
| 503 | `SERVICE_UNAVAILABLE` | 退避，主动备用入口 |

姿势或任务错误还包括：`MODEL_INFERENCE_FAILED`、`GPU_OUT_OF_MEMORY`、`QUEUE_TIMEOUT`、`JOB_DEADLINE_EXCEEDED`、`STORAGE_FULL`、`WORKER_LOST`。运行失败通过任务资源返回，不要求客户端维持一个长 HTTP 请求等待所有 GPU 工作完成。

## 12. 必测契约

1. 相同创建键重发 10 次只产生一个任务、一次配额扣减。
2. 同键换素材被拒绝；不同用户不能看到对方幂等记录。
3. 三姿势数量错误、重复键、错误用途和过期资产在创建前拒绝。
4. 原任务保持不变，重试生成新任务并正确标记复用来源。
5. 超时与取消竞态不能发布已取消/已删除任务的迟到结果。
6. 刷新响应丢失可恢复，不生成不可控的长期明文凭据记录。
7. 删除完成后输入、mask、输出、临时文件和派生引用均不可读取。
8. 旧 revision 响应不会覆盖新状态；进程重启后能找到原任务。
9. 健康接口不暴露配置、密钥、GPU 内网地址或依赖连接字符串。
10. 所有示例占位配方及 Token 在真实部署前被替换，不将此文档当可用服务。
