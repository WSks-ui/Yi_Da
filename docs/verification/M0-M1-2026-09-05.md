## 实际修正

1. 纯手工录入允许 `garment.image_asset_id=NULL`，新增 `thumbnail_asset_id` 外键，避免伪造图片和全尺寸列表解码。业务库尚未发布，v1 基线与生成资源同步修改；后续已发布版本变更必须新增迁移，不能覆盖 v1。
2. API 26 模拟器的 `querySql` 可命中读连接，不能用其返回值验证写连接的 `foreign_keys`。使用 `execute` 验证写连接，并在同一写连接串行执行事务；通过真正的非法外键写入测试确认约束。清理查询必须放到删除事务提交之后，否则会读到旧引用。
3. ImageKit 方向读取显式传 `index:0` 并在解码前读取。测试夹具显式声明 RGBA 输入格式；八种方向均按像素断言，不放宽失败条件。
4. 文件 API 使用绝对路径，ArkUI 展示经 `fileUri.getUriFromPath` 转换；数据库始终只存受校验的相对路径。修复了“文件存在但照片不可读取”。
5. 文件清理失败与数据库提交成功分开报告；下一次启动或“我的”重试，不将已提交保存误报失败。重复目录初始化先检查存在性；重试成功后清除旧警告，含桌面故障恢复断言。
6. 主图保存为长边最多 2048 像素的去元数据 JPEG 副本，缩略图最多 384 像素；不裁剪主体，也不修改系统相册原文件。它不是原始字节备份或已验证的云模型输入。
